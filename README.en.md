# mpsoc-osoc

This is the developer and maintainer repository for `mpsoc-osoc`. It provides
the fixed-address, fixed-bus SoC template and the user-facing distribution
environment generated by CI.

The user distribution contract is maintained in `dev/user-kit/README.md`, with
the English version in `dev/user-kit/README.en.md`. These files are overlaid
into the CI-generated `user-kit` branch, so this README focuses on development,
integration, and publication.

## Repository layout

```text
rtl/                 fixed SoC, MCU, reference CPU, and IP RTL
sim/                 Verilator harness and fast simulation models
prog/                fixed regression image and CPU-ID patch script
user-cores/          local user cores and slot manifest
scripts/             slot assembly and User Kit export tools
dev/user-kit/        user README and Makefile templates
dev/user-kit.json    User Kit files, trees, and override rules
.github/workflows/   CI checks, export, and user-kit publication
build/               local generated files; never commit these
```

The fixed top module is `asicTopYSYXstageDE`, implemented by
`rtl/soc/asicTopYSYXstageDE.v`. The top name is not configured through a
separate metadata file.

## Maintainer checks

Run these targets from the repository root:

```sh
make check
make lint
make sim CPU_ID=0
make trace CPU_ID=0
make export-user-kit
make clean
```

`make check` validates the 32 core slots, user manifest, Verilator, and fixed
`.bin` image. `make lint` checks the assembled simulation design. Full
simulation remains a separate target because the reference image can require
many cycles to finish.

Local `make export-user-kit` is for inspecting the package only. The official
distribution is generated by `.github/workflows/user-kit.yml`; do not commit
`build/user-kit` manually.

## User-core integration

`user-cores/cores.list` uses:

```text
<slot> <module-name> <source-relative-to-user-cores>
```

For example:

```text
0 UserCore0 core0/top.sv
```

Each slot names one top-level source file; multi-file processors include their
other sources from that top-level file. Slots must be consecutive from zero;
unregistered slots keep the reference NPC.

`scripts/assemble-cores.py` writes only to `build/generated/`, never edits the
checked-in SoC top, and adds registered core sources to the generated Verilator
file list.

## User Kit publication

The publication manifest is `dev/user-kit.json`:

- `files` lists individual files to copy;
- `trees` lists fixed RTL directories;
- `exclude` lists paths that must not enter the distribution;
- `overrides` overlays the user README and Makefile at the package root.

The CI `export-and-test` job checks the source tree, exports the kit, and reruns
`make check`, `make lint`, and `make clean` inside the exported directory. Only
after those steps pass on a `main` push does the `publish` job force-update the
`user-kit` branch.

The user branch contains only fixed RTL, the simulation environment, the core
template, the fixed image, the user Makefile, and bilingual README files. It
does not contain `dev/`, maintainer export scripts, build products, version
files, or top-name metadata.

## Integration constraints

- Do not modify `rtl/soc/asicTopYSYXstageDE.v`, the MCU, RCU, bus, peripherals,
  or address decoder.
- Do not modify `prog/change-cpuid.sh`; regression uses the shipped `.bin` image.
- The current release is constrained to the 50 MHz configuration; custom
  `soc_pkg` address spaces are reserved for a future release.
- The submitting user owns simple-bus timing and functional correctness.
